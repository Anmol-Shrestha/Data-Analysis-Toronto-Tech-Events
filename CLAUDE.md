## Project Overview

This is a data analysis project that analyzes Toronto tech/AI events to identify scheduling patterns and optimal days/times for event attendance. The project uses Pandas for data manipulation and Matplotlib/Seaborn for visualizations.

## Dependencies

Install required packages:
```bash
pip3 install pandas matplotlib seaborn plotly streamlit
```

- `pandas` — Data manipulation and analysis
- `matplotlib` — Visualization library
- `seaborn` — Statistical data visualization
- `plotly` — Interactive chart library (for executive report)
- `streamlit` — Interactive web dashboard framework

## Project Structure

- `data/toronto_tech_events_synthetic.csv` — Event dataset
- `dashboard.py` — Streamlit interactive dashboard (deploy to Streamlit Cloud)
- `generate_executive_report.py` — Executive report generator (outputs `index.html`)
- `analyze_events.py` — Command-line analysis script
- `index.html` — Executive report (auto-generated, deploy to GitHub Pages)
- `visualizations/` — Optional PNG outputs from CLI script

## Running Locally

### Interactive Streamlit Dashboard
```bash
streamlit run dashboard.py
```
Launches at `http://localhost:8501` with real-time filtering and exploration.

### Executive Report Generator
```bash
python3 generate_executive_report.py
```
Generates `index.html` with narrative, findings, and recommendations.

### Command-Line Analysis Script
```bash
python3 analyze_events.py
```
Outputs console statistics and PNG visualizations (if needed for reports).

## Code Architecture

**EventAnalyzer Class** — Encapsulates all analysis logic:
- `_prepare_data()` — Cleans data, converts times, establishes day ordering
- `analyze_day_distribution()` — Returns event counts by day of week
- `analyze_time_windows()` — Returns start/end hour distributions
- `get_event_summary_stats()` — Computes key metrics for narrative
- `plot_day_distribution()` — Generates day-of-week visualization
- `plot_time_distribution()` — Generates start/end time visualizations
- `print_summary()` — Outputs formatted findings to console

The class is instantiated in `main()` with the CSV path, then methods are called sequentially to generate all outputs.

## Key Design Decisions

- **Data preparation:** Day-of-week strings are converted to ordered categories to ensure proper sorting in visualizations (Monday-Sunday)
- **Time handling:** Times are extracted as hour integers for aggregation; full datetime objects kept for flexibility
- **Visualization colors:** Blue highlights peak days (top 25% by count), pink/magenta for other days; orange for start times, red for end times
- **Output:** 300 DPI PNG files for presentation quality

## Typical Workflow

1. Place CSV file in `data/` directory with columns: event_id, event_name, category, date, day_of_week, start_time, end_time, venue
2. Run `python3 analyze_events.py`
3. Export charts from `visualizations/` for presentations

## Deployment Options

### Streamlit Dashboard (Interactive Exploration)
Deploy `dashboard.py` to Streamlit Cloud:
- Real-time filtering by day and category
- 4-tab interface for different data views
- CSV download capability
- Live metric cards
- Best for: Team exploration, Q&A, live demos

### Executive Report (Narrative & Findings)
Deploy `index.html` (auto-generated by `generate_executive_report.py`) to GitHub Pages:
- Executive summary highlighting the key story
- Business impact metrics
- Actionable recommendations
- Professional narrative flow
- Best for: Presentations, stakeholder communication, decision-making

GitHub Actions automatically regenerates the report when data changes.

## Design Notes

- Times are aggregated by hour; extend to minutes if finer granularity needed
- Dataset is synthetic; adapt column names/categories for real event data
- Colors and styling configurable in each script
- Both deployments use Plotly for interactive charts (works in static HTML too)
